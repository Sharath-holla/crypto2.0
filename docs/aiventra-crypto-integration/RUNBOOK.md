```powershell
.venv/Scripts/python.exe -m integration.crypto_aiventra.dev status
```

Status reports observed process identities; it does not infer readiness from a stored
RUNNING label. Stop affects only recorded launcher service identities, does not delete
SQLite/artifacts and does not signal independent Crypto scientific workers. Closing
the browser leaves services and approved jobs running. These are local background
processes, not an OS reboot-persistent service; after reboot inspect and restart the
control plane explicitly. Never blindly replay an interrupted job.

## Recovery

Use job evidence, bounded redacted job log tails and explicit reconciliation. Missing
worker/PID creation identity or a stale heartbeat yields INTERRUPTED, not success.
Missing or corrupt completion evidence yields BLOCKED. No metrics are reconstructed
from model-only artifacts. Preserve partial caches, receipts, logs and model files.
Reconciliation records evidence; it does not retrain, delete or replay a command.

Stop is a separately approved exact job/version/hash action. A stop request is not
proof the child has exited: inspect and reconcile its terminal receipt. Resume after
STOPPED/INTERRUPTED/FAILED/BLOCKED requires a new deadline/contract, fresh source scope
and owner approval. If dispatch was uncertain, inspect the same UUID and retained
QUEUED intent; do not approve again. If the authority API is down, workers fail closed
and preserve evidence; reconnecting the UI does not automatically resume them.
