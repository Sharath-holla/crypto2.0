# Native execution and model measurements

## Current zero-cost restriction

Native streaming, tool loops, probes and benchmarks use the same mandatory ZERO_COST_ONLY guard as structured calls. All remote inference is currently denied. The existing external protocol tests use explicitly nonnetwork contract fixtures. Missing free providers retain saved agent/workflow state; benchmarks propagate that wait instead of recording invented rubric results. See ZERO_COST_AI_POLICY.md and the current TEST_REPORT.md. No live remote inference is claimed.


The latest request is preserved in [docs/LIVE_EXECUTION_SPEC.md](docs/LIVE_EXECUTION_SPEC.md). This is the Milestone A native execution/benchmark increment. Phases 3–5 and production verification are still unfinished.

In Models & providers, register documented model capabilities, sensitivity and current input/output rates. Add `streaming` only for an endpoint/model that supports it. Store a real key in the existing vault or configure an actual Ollama endpoint. Provider-free startup remains supported. Consumer subscriptions are not API credentials.

The gateway uses native SSE/NDJSON when streaming is selected. OpenAI Responses, Anthropic Messages, Gemini generateContent, xAI/compatible Chat Completions and Ollama Chat have bounded protocol parsers. Native tools can also use complete JSON responses when streaming is not selected. Streams are bounded to 4 MB, 128 KiB public output, four calls and 16 KiB arguments per call; full native responses are bounded to 1 MB. The existing worker/agent deadlines, at most three gateway attempts, financial reservations and provider allowlists remain enforced. Idle reads time out after 15 seconds; closing a connection does not establish that the provider stopped billing.

Only public output text and function calls are retained. Reasoning text is ignored; Gemini's opaque function-call signature is carried through the next request. Previews hold a tail/unfinished word, redact credentials, truncate at 8 KiB and are explicitly provisional. CEO conversation SSE now includes persisted native traces. Final answers still require schema validation and lease/permission checks. Actual terminal usage is settled before schema failure; missing usage or interrupted billing stays reserved for owner reconciliation. Calls with uncertain usage are never automatically replayed.

In Meetings & messages, Native tool execution selects an approved active project, document-authorized agent, optional exact model and up to eight permitted peers. The server registry permits a bounded calculator, project memory/artifact reads, document writes and one peer document task. Arguments are strictly validated; foreign artifacts, unselected peers, disabled agents, expired approval and arbitrary shell/HTTP tools are rejected. Three model rounds maximum. Each round and tool result is checkpointed. Function-call IDs deduplicate side effects within each checkpointed round. Peer tasks share the original job cap, use the existing document worker and persist an artifact/hash on completion. Cancellation fences pending peer tasks and their workflows as well as the parent; already recorded provider usage remains accounted for. A final tool response is saved as a document, never treated as software delivery or permission to deploy.

The Benchmarks tab queues `micro-v1` against an exact registered real-provider model with an owner spend cap. Eight cases cover simple arithmetic, business/architecture instruction following, coding/repair AST rubrics, testing/review criteria and actual calculator function use/results. Tool support is probed even when not yet declared in registry metadata. One case is checkpointed per worker step; unknown billing stops the suite. Results record run IDs, rubric scores, observed protocol capabilities, latency, current-rate computed costs and reliability. Code is parsed, never run on the host. These small deterministic checks do not evaluate general reasoning, security or production code quality.

Profiles bind at the first attempt, then reject mixed model/price/credential configurations. Waiting without credentials can resume when configured; a partially executed changed suite needs a new request. Profiles expire after 30 days and invalidate when their fingerprint changes. They do not silently grant registry capabilities or relax policy. The router combines current measured quality/reliability/latency with human evaluations and fresh registered prices, then rechecks employee/project/provider restrictions, data sensitivity, context and every spending cap. Economy/balanced/quality recommendations explain their default advice constraints. Manual routing uses only an exact job override or employee preference. Run records retain the actual choice and evidence.

Local verification uses explicitly controlled adapters and fixtures. No live provider account, completed live benchmark or paid-provider invoice was verified. Docker service/database evidence is recorded separately from dedicated generated-code runner evidence in TEST_REPORT.md.
