# Simple project creation

## Model selector isolation — October 11, 2026

Lead and manual/hybrid worker choices use bounded, grouped, searchable radio lists with native keyboard access; worker pools also scroll. Search/provider/availability filters use the shared backend catalog. GPT-6.1 Sol remains a separate unavailable preference; missing saved references are labeled separately. Refresh performs allowed non-inference discovery, reports real counts/errors and preserves selections. Participating roles/departments can be added explicitly. No-provider states navigate to Models & Providers. Existing autosave/version guards and SQLite preference persistence remain.


Home is the default owner landing page. Six primary destinations are Home, New project, My projects, Activity, Approvals and Settings. Advanced retains every existing operating surface and recent conversations; its expansion preference persists locally. Executive chat remains available through New chat and Home.

The three-step wizard saves owner-bound versioned drafts in existing business_records (`kind=project_setup`). Describe accepts typed requirements, UTF-8 TXT/Markdown/CSV/JSON (16 KB each), and bounded main-text DOCX (1 MB source, 256 KB expanded archive, 64 KB text). Six files and 2 MB total are allowed. A two-second extraction response limit accompanies strict byte/entry/compression limits; background parsing is not a general-purpose execution sandbox. Macros/embedded objects/encrypted ZIP/XML DTD/entities are refused. PDF/images remain unavailable. Parsed redacted Artifact content is authoritative; raw-source and content SHA-256, warnings and provenance persist. Source binaries are not retained.

Upload fills an empty brief. Replacement updates an automatically copied brief only when it still matches the prior document; removal clears that copied text. Independently edited requirements are retained. The browser preserves edits made while an attachment request is in flight. Remove/replace commands use exact draft versions/idempotent request envelopes; source artifacts and audit history remain private, and submitted attachments cannot change. Exact proposal approval grants the approved documents to project-scoped memory and assigned agents. Uploads never confer execution authority.

Choose AI saves the preferred GPT-6.1 Sol label without guessing an API identifier or declaring free entitlement. Explicit registered reasoning/structured alternates may be selected, including blocked preferences; only currently eligible real workers can be assigned. Automatic, manual and hybrid modes support an optional pool and role/department overrides. No production wizard fixture mode exists. The gateway still enforces spending, capability, quality, context, reliability, sensitivity, permissions, independent review, concurrency and atomic finance.

Review submits a live requirement and durable consultation, not an approved Project. An unavailable Lead leaves work waiting with no inference. Before inference, paused/waiting work can accept explicit alternate selection; Verify and resume rechecks zero-cost eligibility. Owner-authored planning creates an honestly attributed proposal with no invented AI contributions. Existing exact proposal approval creates the Project; workforce, coding, generated PR, release and closure gates remain separate.

Draft writes serialize through the organization mutex, check expected versions and remember up to 1,000 request fingerprints. Identical retries are idempotent; stale/different payloads are rejected. Browser saves use a serialized queue and retry interrupted saves with the same envelope. Reload explicitly discards local edits after a conflict. The wizard warns before unloading unsaved work and attempts a queued save on internal navigation. Server durability determines Saved status.

Five project stages expose Requirements, Planning, Engineering, QA & review and Delivery. They reuse staffing, task board/timeline, restricted engineering, final review, immutable package, release and follow-up controls. Successful execution counts require a persisted completed execution with exit code zero; they do not imply final QA acceptance or delivery.

Engineering now supports authorized read-only GitHub URL/branch analysis through the existing connector; saved project repositories can be referenced by the wizard. Metadata-only entries require a separate managed checkout before coding. Planning supports task-specific model assignments and explanations through the existing workforce UI. Limits remain secure PDF ingestion, remote checkout, measured resource forecasting, staging/binary export and genuine local AI/client delivery. No installation or free-provider entitlement claim is added. Optional consultation specialists remain bounded to three roles.

Owner-only API: `/project-creation-options`, `/project-drafts`, `/project-drafts/{id}`, `/attachments`, `/submit`, `/models`, `/manual-plan`. Web mutations remain origin-protected. Generic record updates cannot change project_setup records. No schema migration or PostgreSQL cutover is introduced. See TEST_REPORT.md for observed checks.
