# Persistent semantic memory

Memory source writes and source-version records share the original database transaction. Requirements, proposals, artifacts, business knowledge, task status/evidence, conversation turns, meetings and task workflow errors/resolutions are captured. A durable bounded keyset backfill also covers existing records and SQL bulk updates. Owner-authored knowledge, architecture decisions, resolutions and private agent notes use the same system. Source summaries are explicitly bounded extracts, not model-generated claims.

Five additive tables hold current entries, immutable-by-API versions, overlapping chunks, explicit agent grants and backfill cursors. PostgreSQL enables `vector`, stores `vector(384)` and creates a cosine HNSW index. SQLite uses JSON vectors and bounded exact cosine ranking for development; PostgreSQL is the intended deployment database. All query paths join only the current source version and filter tenant/project/agent/conversation access before ranking. Owner-only conversation evidence is excluded from general project memory. Selected grants and private agent notes cannot cross their project boundary. Source revisions invalidate embeddings; a fingerprint prevents vectors from different configured models from mixing.

`EMBEDDING_PROVIDER=fastembed` uses the CPU-local BAAI/bge-small-en-v1.5 model. Install dependencies with `uv sync --extra dev --extra local-embeddings`, then explicitly prepare weights with `python -m company_os.embeddings --download`. The application never downloads weights during startup or a memory search. Compose includes the dependency and a persistent shared embedding-cache volume. `ollama` supports an explicitly local `/api/embed` endpoint and a configured 384-dimensional model. `disabled` provides honest keyword retrieval. No paid provider credential is required. `deterministic_test` is permitted only under test configuration and is visibly labeled; its hash features are not semantic-model evidence.

The worker indexes bounded batches off the workflow event loop. Missing models record `waiting_for_local_model`; keyword search and stored history continue to work. New/unindexed source versions can join vector results as labeled keyword matches. Actual model context includes bounded, untrusted retrieval evidence with source IDs, versions and hashes; it never grants permission or silently enlarges a financial/context cap. Uncertain paid calls retain the existing reconciliation behavior.

The Semantic memory UI supports scoped search, agent-access inspection, manual notes/decisions, optimistic versioned edits, history, bounded indexing and content purge. Source-backed records are edited through their source workflow. Purge removes version text/vectors/grants and retains a source tombstone/hash plus audit, preventing automatic re-import. Original source documents are separate records and are not deleted by a memory purge.

Local model weights were downloaded and real 384-dimensional inference was observed on this Windows host. Automated tests separately use explicit deterministic vectors. CI's `verify_semantic_memory.py` requires actual PostgreSQL/pgvector/HNSW, checks real local paraphrase ranking, then compares the saved entry/version/vector digest and retrieval after service restarts. Exact observed results are recorded in TEST_REPORT.md; code alone is not a passing Docker check.

Limits: the configured model must output 384 dimensions; the default small English model is not a multilingual/domain-quality certification. SQLite exact ranking bounds candidate scans at 2,000 chunks. UI browsing currently shows the latest 100 entries, while search ranks scoped chunks. Backfill/index batch sizes bound load; broad production recall/load/retention-policy certification remains future operational work. No live paid-provider success is claimed.
